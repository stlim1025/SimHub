다시보기 3D 화면을
three.js로 바꾸는 설계

이 문서는 랩 다시보기와 레이스 하이라이트의 3D 화면을 three.js(WebGL) 엔진으로 옮기는 방식을 정한다. 결정 시트의 네 가지를 정해 주면 1단계부터 구현한다.

결정 시트결정란은 직접 기입한다
안건권장결정

4진행 순서다섯 단계로 나누고 단계마다 화면을 보고 넘어간다
1

지금 구조와 한계

지금 3D 화면은 GhostReplay3dPainter(1,262줄)가 Flutter 캔버스에 직접 그린다. 3D 엔진 없이 면을 하나씩 화면에 투영하고 먼 면부터 덮어 칠한다(화가 알고리즘). 깊이 버퍼가 없어서 면이 겹치는 곳마다 칠하는 순서를 손으로 맞춰야 한다. 면마다 밝기가 하나라서 곡면이 각져 보인다. 차도 상자와 단면 몇 개를 이은 모양이라 블록처럼 보인다. 질감(텍스처), 그림자, 반사도 없다.

이 페인터는 두 화면이 함께 쓴다. 랩 다시보기(ghost_replay.dart)와 레이스 하이라이트(session_highlights_page.dart)다. 두 화면이 넘기는 입력은 같다. 트랙 모양(ReplayTrack3d), 차의 움직임(ReplayCar: 시간마다 위치·방향·보임 여부), 카메라 종류(추격·중계·헬기), 경과 시간, 차 색, 둘레 차와 이름표다.

권장

이 입력을 경계로 삼는다. 그러면 두 화면의 나머지 코드는 건드리지 않고 그리는 부분만 바꿀 수 있다.

2

구조

Dart가 무엇을 그릴지 정하고 three.js는 그리기만 한다.

Dart 쪽
트랙 메시 데이터(꼭짓점·색·재질 구역)를 ReplayTrack3d에서 한 번 만들고 매 프레임 차 위치·방향·바퀴 조향과 카메라 위치·화각을 계산한다. 지금 페인터에 있는 카메라 계산(추격·중계·헬기)을 순수 함수로 떼어 내 그대로 쓴다. 순수 계산이라 단위 테스트로 지킨다.
JS 쪽
web/replay3d/replay3d.js 모듈 하나. 장면을 만들고 트랙 데이터를 받아 메시를 만든다. 매 프레임 받은 상태로 차와 카메라를 옮겨 그린다. 판단하는 코드는 두지 않는다.
연결
Flutter web의 플랫폼 뷰(HtmlElementView)로 <canvas>를 화면에 넣고 dart:js_interop로 JS 모듈 함수를 부른다. 트랙은 처음 한 번 Float32Array로 넘기고 매 프레임에는 차와 카메라 상태를 담은 작은 Float32Array 하나만 넘긴다.
겹쳐 그리는 것
HUD, 순위표, 자막, 깃발 띠, 이름표는 지금처럼 Flutter 위젯으로 3D 캔버스 위에 얹는다. 이름표의 화면 위치는 Dart가 같은 카메라로 투영해 계산하므로 앱 글꼴을 그대로 쓴다.

확인 필요Flutter web에서 플랫폼 뷰 위에 Flutter 위젯을 겹치면 렌더러에 따라 합성 비용이 든다. 1단계에서 실제 프레임 속도를 재서 확인한다. 3D 캔버스 위의 터치·스크롤 이벤트 처리도 같이 확인한다.

3

엔진과 배포

three.js 0.186.1(MIT 라이선스, 2026-09-24 배포)을 app/web/vendor/three/에 넣어 GitHub Pages와 같이 배포한다. 외부 CDN에 기대지 않는다. 필요한 파일은 three.module.min.js(393KB)와 three.core.min.js(416KB)이고 gzip으로 합쳐 약 195KB다. 하늘(Sky) 같은 보조 모듈은 three.js 저장소의 examples/jsm에서 필요한 것만 같이 넣는다.

권장

다시보기 카드가 처음 3D 시점을 그릴 때 동적으로 불러온다. 그래서 앱 첫 화면 로딩에는 영향이 없다.

4

차 모델

라이선스가 확실한 공개 F1 모델은 찾지 못했다. CC0 F1 모델은 검색에서 나오지 않았다. TurboSquid 무료 모델은 자체 라이선스이며 다른 무료 F1 모델은 라이선스 표기가 없었다.

A. 코드로 직접 만든 모델권장

  • 라이선스 걱정이 없다
  • 팀 색·타이어 컴파운드 색·바퀴 회전·앞바퀴 조향을 코드에서 바로 바꿀 수 있다
  • 모양을 다듬는 데 시간이 든다(2단계 전체)

B. 외부 공개 모델(glTF)

  • 처음부터 세부가 많을 수 있다
  • 조건에 맞는 모델을 찾지 못했다. 찾더라도 모델마다 라이선스를 확인해야 한다
  • 팀 로고·번호가 들어 있으면 지워야 하고 부품별 색 바꾸기가 모델 구조에 달려 있다

모양(현행 F1 비율: 길이 약 5.6m, 폭 2m, 휠베이스 3.6m):

  • 노즈와 모노코크: 단면 여러 개를 이어 매끈한 곡면으로 만들고 부드러운 법선을 준다.
  • 사이드포드(아래를 파낸 언더컷), 엔진 커버와 에어박스, 샤크 핀.
  • 헤일로: 관 모양(TubeGeometry).
  • 앞날개와 뒷날개: 익형 단면을 밀어 낸 여러 장의 날개판과 엔드플레이트, 뒷날개 DRS 플랩.
  • 바닥과 디퓨저, 서스펜션 암, 미러, 헬멧.
  • 타이어: 회전체(LatheGeometry)로 둥근 숄더를 살리고 옆면에 컴파운드 색 띠와 휠 커버.

재질: 몸체는 팀 색에 클리어코트를 준 물리 기반 재질, 날개·바닥은 카본 무늬 텍스처(코드로 생성), 타이어는 무광 고무. 팀 로고, 번호, 스폰서는 넣지 않는다.

움직임: 바퀴는 속도만큼 돌리고 앞바퀴는 트레이스의 스티어 값만큼 꺾는다. 고스트 차는 반투명으로 그린다.

5

트랙과 환경

트랙 모양은 지금처럼 ReplayTrack3d(가장자리·높이·연석·그래블·방호벽 위치)에서 만든다. 데이터는 그대로 두고 표현만 바꾼다.

요소표현
아스팔트코드로 만든 노이즈 텍스처와 미세한 거칠기
연석빨강·흰 줄무늬에 살짝 솟은 단면
선흰 가장자리 선, 출발·결승선, 피트 레인
그래블·잔디자갈 질감, 깎은 줄무늬가 보이는 잔디
방호벽일반 서킷은 타이어 배리어와 가드레일, 시가지 서킷은 콘크리트 벽과 펜스
환경하늘, 해 방향의 그림자(카메라 둘레만), 거리 안개, 영화 같은 톤 매핑(ACES), 안티앨리어싱

관중석, 나무, 건물 같은 장식은 이번 범위에 넣지 않는다.

6

성능

목표는 데스크톱 60fps, 휴대폰 30fps 이상이다. 기기 픽셀 비율은 2로 제한하고 그림자 해상도와 안티앨리어싱은 화면 크기에 맞춰 낮출 수 있게 한다. 하이라이트는 차가 최대 22대라 차 지오메트리를 모든 차가 함께 쓰고 재질 색만 바꾼다. 화면에서 보이지 않을 때(탭 전환, 스크롤로 벗어남)는 그리기를 멈춘다.

확인 필요휴대폰 실기기 성능은 1단계 뒤 직접 열어 보고 판단한다.
